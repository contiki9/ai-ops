# Grill Me

実装に入る前に、要件・制約・優先順位を対話で収束させるためのスキルです。

## 使いどころ

- 要件が曖昧なまま実装に進みそうなとき
- 仕様の抜け漏れや前提のズレを事前に潰したいとき
- MVP と将来拡張の境界を明確にしたいとき

## 対象外（責務の境界）

- `commands/` 向けコマンド作成は行わない（`skills/create-command` の責務）
- 作業後のレビュー運用は行わない（`skills/gemini-code-review` の責務）
- 実装コードの自動生成を主目的にしない（本スキルは要件収束が主目的）

## 対話ルール（最重要）

1. 一度に質問は1つだけ行う
2. 各質問には「推奨回答案」を必ず添える
3. コードベース探索で答えられる内容は、質問より先に調査する
4. 合意形成が済むまで、論点を枝分かれ順に深掘りする
5. 各ターンは簡潔にし、冗長な長文質問を避ける

## 質問カテゴリ（基本順序）

1. 背景と課題: 何が困りごとか、なぜ今やるのか
2. 成功条件: 何をもって完了/成功とするか
3. スコープ境界: 今回やること/やらないこと
4. 制約と依存: 既存仕様、外部連携、性能・運用制約
5. エッジケース: 失敗系、例外系、データ欠損時の扱い
6. MVP優先度: 最小実装と後続フェーズの切り分け

必要に応じて順序を入れ替えてよいが、最低でも「成功条件」「スコープ境界」「エッジケース」は確認する。

## 1ターンの出力フォーマット

以下の形式で返答する。

```md
質問: <1つの質問>
推奨回答案: <現時点のベスト案。根拠を1-2文で簡潔に>
```

## 打ち切り条件（実装フェーズへ移行する条件）

次を満たしたら質問を終了し、合意サマリを提示して実装フェーズへ移行する。

- 課題・目的が明確
- 成功条件（受け入れ基準）が明確
- 今回スコープ/非スコープが明確
- 主要制約と依存関係が明確
- 主要エッジケースへの方針が明確

## 終了時の必須出力

質問終了時は、以下を日本語で短くまとめる。

- 合意した要件
- 非スコープ
- 未確定事項（残っている場合のみ）
- 次アクション（実装/調査/意思決定）

## 利用例（呼び出しプロンプト）

```text
/grill-me
次の機能案について壁打ちしてください。
質問は必ず1問ずつにし、毎回推奨回答案を添えてください。
コードベースで分かることは先に調査し、合意形成できたら要件を要約して実装フェーズに進めてください。
```
