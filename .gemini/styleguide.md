# Gemini 共通指示・スタイルガイド

本ドキュメントは、Gemini への応答品質を安定させ、再利用性と一貫性を保つための標準ガイドラインです。
Gemini を利用する際は、以下の指示を基本ルールとして適用してください。

## 1. 応答言語とトーン＆マナー

- **言語**: すべての応答、コードレビュー、説明、ドキュメント作成は**日本語**で行ってください。
- **トーン**: **丁寧語（です・ます調）**を使用し、**プロフェッショナル**かつ誠実なトーンで回答してください。
- **提案の根拠**: コードの修正や構成の変更を提案する際は、その**理由・背景を簡潔に**添えてください。

## 2. プルリクエスト (PR) 説明文の作成

プルリクエストを作成または更新する際は、以下のルールに従ってください。

- **自動生成**: PR 開始時は、提供された diff 情報に基づき、日本語で PR 説明文の草案を作成してください。
- **テンプレート準拠**: PR 説明文は、リポジトリ内の `.github/PULL_REQUEST_TEMPLATE.md` のフォーマットに必ず準拠してください。
  - 概要/対応issue
  - 変更内容（追加・変更・削除したファイルを含む）
  - テストの観点
  - 影響範囲
  - 動作要件
  - 補足

## 3. プルリクエスト作成前の品質確認

プルリクエストを作成または更新する前に、以下の品質確認を実施し、その結果を報告してください。

- **品質確認の実施**: 対象の変更内容に応じた適切な品質確認（ユニットテスト、統合テスト、Lint チェック、型チェックなど）を実施してください。
- **手法の柔軟性**: 品質確認の手法は、プロジェクトの環境や技術スタックに合わせて最適なものを選択してください。特定のコマンドに厳密に固定するものではありません。
- **結果の報告**: 実施した確認内容とその結果（パスしたか、どのような修正を行ったか等）を、ユーザーへの報告や PR 説明文に含めてください。

## 4. 運用ルール（備考）

- **更新責任者**: 本リポジトリのメンテナが管理します。
- **更新タイミング**:
  - Gemini の挙動に著しい変化があった場合
  - チーム内で新しい応答ルールが必要と判断された場合
  - PR テンプレートが変更された場合
- **他モデルとの差分**: 他の AI モデル（Claude 等）向けのガイドラインが必要になった場合は、ディレクトリを分けて管理するか、本ファイル内で明示的に切り分けてください。
